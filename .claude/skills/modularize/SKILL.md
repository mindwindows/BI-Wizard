# modularize — 모듈 경계와 API 계약 설계

## 목적
기능 구현 전에 모듈과 Skill의 경계, 프런트·백엔드가 맞춰 쓸 API 계약을 정한다. 경계가 흐리면 기능마다 코드와 Skill이 어긋난다.

## 사용 조건
- Gate ③에서 실행할 때
- 승인된 계약을 바꿔야 할 때 (이 경우 변경 전후를 비교하고 사용자 승인을 받는다)

## 모듈 경계 기준
- 화면, API, 비즈니스 로직, 데이터 접근을 기능 단위로 나눈다.
- 한 모듈은 하나의 사용자 기능에 대응한다. 여러 기능이 같은 데이터 접근 코드를 쓰면 공통 계층으로 빼되, 미리 추상화하지 않는다.
- 새 기능을 붙일 때 기존 핵심 코드를 크게 건드리지 않도록 확장점을 명시한다. 예: 수식 함수 등록 방식, 타입 추가 방식.

## Skill 경계 기준
- 사용자 관점에서 독립적으로 수행되는 기능마다 Skill을 하나 둔다.
- 예상 단위(확정은 이 단계에서): 엑셀 가져오기, 데이터셋 정의, 수식 열, 데이터 입력, 대시보드 연결, 권한 관리
- 내부 helper마다 Skill을 만들지 않는다. "AI가 하나의 작업으로 쓸 수 있는 기능 단위"가 기준이다.

## 산출물 형식

### 1. 모듈 경계표
| 모듈 | 책임 | 화면 | API | 데이터 접근 | 확장점 |
| --- | --- | --- | --- | --- | --- |

### 2. 기능↔Skill 대응표
| 기능 | 대응 Skill (`skills/<기능>/`) | 주요 UI | 주요 API | 주요 DB | 연관 Skill |
| --- | --- | --- | --- | --- | --- |

### 3. REST API 계약
엔드포인트마다 다음을 적는다.
- 메서드와 경로 (예: `POST /api/datasets/{id}/rows`)
- 권한
- 요청 본문과 필드 타입
- 성공 응답 구조
- 오류 응답 구조와 주요 오류 코드
- 관련 기능과 Skill

응답 구조는 프런트 훅이 그대로 읽을 수 있도록 필드 이름과 타입을 고정한다. 필드를 나중에 추가하는 것은 허용하지만, 기존 필드 이름 변경은 계약 변경으로 본다.

### 4. 데이터 모델
- 등록 테이블 메타데이터: 소유자, 원본 파일, 생성일, 스키마
- 데이터셋 정의: 열 이름, 타입(텍스트, 숫자, 날짜, 참/거짓, 선택 목록, lookup), 검증 규칙(필수, 범위, 정규식, 유일성)
- 수식 열: 수식 원문, 파싱 결과, 의존 열 목록
- 열 이름 변경 시 수식 연쇄 수정에 필요한 참조 정보

### 5. 기능 단위 목록
의존 순서대로 나열한다. 각 단위는 Skill 하나에 대응하며, 완료 기준은 `feature-unit` 스킬을 따른다.

## 미결정 사항 처리
- 브리프 5절 2번(수식 범위 첫 버전: 같은 행 / 다른 표 참조 / 집계)은 옵션마다 데이터 모델과 난이도 차이를 적고 확정하지 않는다.
- 3번(새 데이터셋 생성 권한)도 옵션(편집자 전원, 관리자, 팀별 담당자)과 영향만 적는다.
- **마이그레이션 D2(동적 객체 분리 방식)** 는 이 Gate에서 데이터 모델과 함께 사용자가 결정한다(`docs/decisions/03-migration-tool.md`). 옵션 S(별도 schema), N(이름 규칙 + 필터), R(등록 테이블 기반), D(별도 DB)의 장단점과, 읽기 전용 계정(D7)의 `SELECT` 권한 부여 방식, 수식 → 뷰 변환 규칙 변경 시 기존 뷰 재생성 방식을 같이 적는다. 결정 전에는 자동 생성 초안의 `DROP`을 사용자 확인 없이 적용하지 않는다.
- 6번(저장 전 수식 평가 경로)과 7번(Explore 제공 방식)도 이 Gate의 결정 대상이다. 옵션과 영향만 적는다.
- `gate-status.md`의 "Gate ③ 인계 사항"(붙여넣기 파서 따옴표 안 탭, 순환 검사기 raw SQL, RLS `clause` 미검증, `CREATE VIEW` 렌더링 근거 확인)을 설계에 반영한다.

## 검토 체크리스트
- [ ] 모든 API 엔드포인트가 하나 이상의 기능에 대응한다.
- [ ] 모든 기능 단위에 Skill이 있다.
- [ ] 프런트가 호출하는 경로와 백엔드 경로가 같다.
- [ ] 브라우저에서 DB나 Superset 내부를 직접 호출하는 경로가 없다.
- [ ] 미결정 사항을 확정하지 않았다.
