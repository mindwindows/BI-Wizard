# 합성 샘플 (붙여넣기 파서·엑셀 가져오기 시험의 시작 자료)

Gate ④ 에서 붙여넣기 파서(`frontend/src/paste/`, 예정)와 엑셀 가져오기(`backend`)를 시험할 때 쓰는 **합성 샘플**이다.
Gate ③ 4라운드에서 사용자가 "실제 회사 자료 대신 세션이 만든 합성 샘플"로 정했다(미해소 항목 U-1 클립보드 샘플, U-2 엑셀 샘플의 대체).

> **한계 (먼저 읽을 것)**
> - 모두 **합성 데이터**다. 실제 회사 자료가 아니며, **실제 Excel·Teams 클립보드와 실제 업무 엑셀 파일로 검증하지 않았다.**
> - `clipboard-cases.json`의 `raw` 값은 "Excel이 이렇게 직렬화할 것"이라는 **가정**이다(아래 "가정 목록"). 실제 클립보드 텍스트와 다르면 `raw`를 고쳐야 한다.
> - 엑셀 파일은 `openpyxl`이 만든 작은 파일(최대 37행)이다. 규모·성능 시험용이 아니다(대용량 시험 파일은 저장소에 두지 않는다).
> - 실제 자료가 생기면 이 샘플을 대체하거나 보강한다. 이 샘플의 통과는 "실제 파일에서도 동작한다"는 근거가 되지 않는다.

## 파일

| 파일 | 설명 |
| --- | --- |
| `clipboard-cases.json` | 붙여넣기 파서 사례 42건. Excel 클립보드 `text/plain`(탭 구분) 형식을 가정한 `raw`와 기대 결과 |
| `generate_samples.py` | 아래 xlsx 4개를 만드는 스크립트(`openpyxl` 필요, 저장소 requirements에는 넣지 않음) |
| `synthetic-team-monthly.xlsx` | ① 팀 월별 실적: 한글 머리글 5개, 월 열은 월 첫날 날짜, 숫자 열 2개, 합계 수식 열, 36행 |
| `synthetic-messy-merged.xlsx` | ② 지저분한 표: 제목 행(병합), 빈 행, 두 줄 병합 머리글, 데이터 중간의 빈 행, 합계 수식 행, 맨 아래 주석 행(병합) |
| `synthetic-multi-sheet.xlsx` | ③ 시트 3개(요약/데이터/설명): 요약은 데이터를 집계하는 수식, 데이터는 주문 30건, 설명은 안내 문구 |
| `synthetic-mixed-types.xlsx` | ④ 혼합 형식: 날짜, 일시, 앞자리 0이 있는 문자열 코드, 정수, 소수, 퍼센트, 참/거짓, 선택 목록(데이터 유효성) 텍스트, 빈 칸 섞인 비고, 수식 열, 모서리 값(큰 수 `1.23456789012345E+15`, 음수, `0.001%`) |

## xlsx 생성 방법

```bash
pip install openpyxl==3.1.5            # 이 스크립트 전용. requirements에는 추가하지 않는다.
python docs/samples/generate_samples.py --verify     # 생성 + 다시 읽어 검증
python docs/samples/generate_samples.py <출력폴더>     # 다른 폴더에 생성
```

- 난수 시드와 파일 속성의 시각을 고정해 같은 `openpyxl` 버전이면 **같은 바이트**가 나온다(작성 시 두 번 생성해 `sha256`이 같음을 확인).
- `openpyxl`은 수식의 계산 결과를 파일에 쓰지 않는다. 그대로면 `data_only=True`로 읽을 때 수식 셀이 빈 값이 되어 실제 Excel이 저장한 파일과 달라진다. 그래서 스크립트가 **수식 결과를 파이썬으로 계산해 시트 XML의 `<v>`에 넣는다**(Excel이 계산한 값이 아니다).

### 검증 결과 (작성 환경: Python 3.13 + openpyxl 3.1.5, `--verify` 24개 항목 모두 통과)

`openpyxl.load_workbook(read_only=True, data_only=True, keep_links=False)`로 다시 읽어 확인했다(병합 범위·데이터 유효성은 읽기 전용 모드에서 보이지 않아 일반 모드로 확인).

| 파일 | 확인한 내용 | 크기 |
| --- | --- | --- |
| ① team-monthly | 시트 1개·37행(머리글 + 36), 한글 머리글, 월 열은 모두 `datetime`이며 1일, 합계 열 캐시 값 = 상품매출 + 서비스매출 | 6.4KB |
| ② messy-merged | 1행 제목·2행 빈 행, 병합 머리글(병합 범위의 오른쪽 셀은 `None`), 완전히 빈 행 3개(2·9·13행), 합계 수식 캐시 값, 병합 범위 7개(일반 모드) | 5.5KB |
| ③ multi-sheet | 시트 이름 `['요약','데이터','설명']`, 요약 수식 캐시 값의 합이 데이터 시트와 일치(30건) | 8.0KB |
| ④ mixed-types | 날짜·일시는 `datetime`, 코드 열은 `str`(`00012` 보존), 수량 `int`·단가 `float`, 배송완료 `bool`, 상태는 선택 목록 값 4종, 비고에 빈 칸과 값 혼재, 금액 수식 `float`, 데이터 유효성 1개(일반 모드) | 7.2KB |

각 파일 100KB 미만, 총 합계 30KB 안팎이다.

## clipboard-cases.json

### 구조

```json
{ "_readme": "...", "format": { ... }, "cases": [
  { "name": "...", "description": "...", "raw": "a\tb\r\nc\td\r\n",
    "expected": [["a","b"],["c","d"]], "notes": "..." } ] }
```

- `raw`: 클립보드 `text/plain` 원문. JSON 문자열이므로 `\t`, `\n`, `\r\n` 이스케이프를 쓴다(읽으면 실제 제어 문자가 된다).
- `expected`: 파서가 돌려줄 행×열 문자열 2차원 배열. 빈 입력은 `[]`.
- **거부 사례**(`unclosed_quote`, `backtrack_then_unclosed`, `nul_character`)는 `expected: null`이고 `expected_error`에 메시지 예시가 있다. 문구는 예시이며 확정이 아니다.
- `reference_parser_diff`가 있는 항목(2건)은 참고 코드(`references/react-datasheet-grid/src/utils/copyPasting.ts`)와 요구사항이 다른 지점이다. 참고 코드는 이식하지 않는다.
- 사례 이름과 골든 케이스의 대응은 각 `notes`에 적었다. 요구사항·골든 케이스의 출처는 `_workspace/gate3/round4-options.md` 5-(a)(Git 제외 폴더)다.

### 가정 목록 (실제 Excel로 확인하지 못함)

1. Excel은 선택 영역을 `text/plain`에 **탭(셀)과 CRLF(행)**로 넣고, 마지막 행 뒤에도 CRLF를 붙인다.
2. 셀 값에 `"`, 셀 안 줄바꿈(LF), 탭이 있으면 셀 전체를 `"`로 감싸고 안의 `"`를 `""`로 바꾼다. (탭 포함 시 감싸는지는 확실하지 않다. 요구사항 쪽은 "넓게 감싼다"고 가정했다.)
3. **쉼표는 감싸는 조건이 아니다**(탭 구분이므로).
4. 클립보드에는 **서식이 적용된 표시 텍스트**가 들어간다(날짜 `2026년 10월 11일`, 숫자 `1,234.50`, 퍼센트 `12.5%`, 통화 `₩1,000`). 표시 형식 때문에 정밀도가 잘렸을 수 있다.
5. 단독 CR은 Excel이 만들지 않는다고 보지만 다른 출처(웹, 메신저)에서 올 수 있어 사례에 넣었다.
6. Teams·웹 앱 등 다른 출처는 LF만 쓰거나 끝 개행이 없을 수 있다(`basic_table_lf_no_trailing`).

### 요구사항과 어긋나는 모서리 (참고 코드와의 차이, 파생 사례)

- `tab_in_cell`: Excel이 감싸는 것으로 가정한 탭 포함 셀. 요구사항은 따옴표 안 탭을 셀 내용으로 보고, 참고 코드는 탭에서 나눈다.
- `crlf_lf_cr_mixed`: 참고 코드는 `\r`을 모두 지워 행이 합쳐진다.
- 골든 표에 없는 **파생 사례**(요구사항 문장을 직접 적용한 결과): `two_trailing_newlines`, `only_newline`, `backtrack_then_unclosed`. 파서를 새로 쓸 때 합의가 필요한 모서리이므로 `notes`에 그렇게 표시했다.

### 기대값 교차 확인

기대값은 손으로 쓴 뒤, 5-(a) 요구사항 7개를 그대로 옮긴 **일회용 상태 기계 참조 구현(Python, 저장소에 두지 않음)**으로 42건을 돌려 **42건 모두 일치**함을 확인했다. 두 구현이 같은 요구사항 문장에서 나왔으므로 요구사항 자체가 잘못이면 이 확인으로는 잡히지 않는다. 같은 입력에서 TypeScript 구현과의 일치는 Gate ④에서 확인한다.

## 사용 위치 (Gate ④)

- `clipboard-cases.json`: 프런트 붙여넣기 파서 단위 시험의 데이터 구동 입력(`raw` → `parse()` → `expected`). 속성 시험·퍼징은 골든 케이스와 별도로 만든다.
- `synthetic-*.xlsx`: 백엔드 가져오기(미리보기 → 확정)의 시험 입력. 시트 선택, 병합 머리글, 빈 행, 날짜·소수·참거짓·문자열 코드 추론, 수식 캐시 값(`data_only=True`) 동작을 본다.
- 큰 파일(5/10/20MB)과 변조 파일(압축 폭탄 등)은 저장소에 두지 않았다(`_workspace/`, Git 제외).
