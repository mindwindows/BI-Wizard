## 1. 범위와 처리 흐름
- FU-1은 **같은 행 수식만**(`03b` 5-1). 열마다 수식 하나, 결과는 계산 열(`kind=formula`), 뷰 열 이름은 `c_<번호>`(K12 (나), 표시 이름 갱신 확인됨: 03c A-27).
- 문법 **[제안]**: 열 참조 `[열 이름]`(저장은 열 번호 참조 AST라 이름 변경에 안 깨짐, 03b 1-6; 열 이름에는 `[` `]` `"`·제어문자를 쓸 수 없게 해 수식 보기 `text`를 다시 읽어도 깨지지 않음, 06 §3-3), 글자 `"…"`(안의 `"`는 `""`), 숫자 `1234.5`, `TRUE`/`FALSE`, 함수 호출 `NAME(…)`(문법은 함수 이름을 모르고 사전이 해석). **날짜 상수와 `NULL` 상수는 없다**(날짜는 `DATE()`, 빈 값은 열 값에서만 생김). 우선순위는 엑셀과 같음(비교 < `&` < `+ -` < `* /` < 부호).
| 단계 | 하는 일 | 위치 |
| --- | --- | --- |
| 1 파싱 | `lark`(MIT, 브리프 4.5) 문법 → AST(열 번호 참조) | formula |
| 2 C0 정적 검사 | 이름·타입·인수·상수 오류·글자 규칙·순환(§7). 자동완성·쉬운 말 오류의 원천(`03b` 2-3 W7) | formula |
| 3 변환 | AST → (값 식, 오류 식) SQLAlchemy 표현식. 참조된 계산 열은 **펼쳐서(인라인)** 각 식이 원본 열만 읽음. 펼친 노드 2,000 초과는 C0 거부 **[제안]**. 문자열 조립 없음(브리프 4.5, D3) | formula |

## 2. 함수 사전 (`03b` 5-2 K6: 함수 추가 = 사전 항목 1개 + 시험 사례)
### 2-1. 사전 항목 필드 (연산자도 같은 구조)
| 필드 | 내용 |
| --- | --- |
| `name`, `signature` | 수식 이름, 인수 목록(이름·허용 타입 number/text/boolean/date·필수/반복·상수 필수 여부), `returns`(타입 또는 규칙) |
| `null_policy` | `propagate`(기본: 어느 인수라도 비면 결과도 빔, 사전 공통 감싸기가 처리) / `skip`(FU-1 함수는 쓰지 않음, 후속 "건너뛰는 합계"용) / `custom`(IF·AND·IFERROR 등 직접 처리) |
| `error_when` | (조건 식, 오류 코드) 목록. 평가 순서: 인수 오류 > 인수 빈 값 > 자기 조건. 오류 식은 값 식과 같은 구조(IF는 고른 쪽만) |
| `to_sql` | 인수 표현식 → 값 식. SQLAlchemy 내장 구성요소만, 상수·NULL은 §4-1 렌더러 경유 |
| `excel_diff`, `help_ko` | 엑셀과 차이, 편집기·수식 도움말 문구(도움말은 사전에서 자동 생성) |
| `cases` | 시험 사례(필수): 입력(상수·열 값·빈 값) → 기대 값 또는 오류 코드 또는 C0 거부 |
- 추가 절차: ① 사전 항목 1개 + `cases` 작성 ② 시험 실행(항목 완결성 검사 + §6 차분 매트릭스가 자동 확대) ③ 끝. 파서·C0·변환기·편집기·도움말은 수정하지 않는다. 변환 결과 SQL이 바뀌면 해시가 달라져 시작 때 해당 뷰만 재생성된다(§8).
### 2-2. FU-1 함수 세트와 제안 이름 (엑셀 이름 그대로, `SUMTAG`만 새 이름 **[제안]**)
| 이름 | 인수 → 반환 | 빈 값 | 오류 조건 | 엑셀과 차이 | 값 식 요지 |
| --- | --- | --- | --- | --- | --- |
| `+ - *` | 숫자,숫자→숫자 | 전파 | - | 빈 칸만 다름 | `a+b` (결과 `NUMERIC`) |
| `/` | 숫자,숫자→숫자 | 전파 | b=0 (E1) | 엑셀 #DIV/0!, 여기는 오류 칸 | `a / NULLIF(b, 0)` |
| `= <>` | 같은 타입 2개→참거짓 | 전파 | - | 글자는 대소문자 무시 | 글자 `lower(a) = lower(b)` |
| `< <= > >=` | 숫자 또는 날짜→참거짓 | 전파 | - | 글자 대소 비교는 FU-1 제외(정렬 규칙 DB 의존) | 직접 비교 |
| `&` | 글자,글자→글자 | 전파 | - | 숫자를 글자로 자동 변환하지 않음(안내 오류) | `a \|\| b` |
| `IF(조건,참,거짓)` | 참거짓,T,T→T | custom: 조건이 비면 결과 빔 | 고른 쪽만 | 엑셀은 빈 조건을 거짓으로 봄 | `CASE WHEN c IS NULL THEN NULL(형 있음) WHEN c THEN a ELSE b END` |
| `AND OR NOT` | 참거짓→참거짓 | 전파(AND·OR는 하나라도 비면 빔) | - | 엑셀은 빈 칸을 무시 | 전파 감싸기 + `AND`/`OR`/`NOT` |
| `IFERROR(값,대체)` | T,T→T | custom: 오류 칸이면 대체값, 빈 값은 그대로 | - | 같음 | `CASE WHEN err(v) IS NOT NULL THEN alt ELSE v END` |
| `ROUND ROUNDUP ROUNDDOWN(수,자릿수)` | 숫자,정수 상수(-10~10)→숫자 | 전파 | - | 자릿수는 상수만. 반올림 방향은 0에서 먼 쪽(PG `round` 동작은 추정, 시험으로 확인) | `round(x,n)`, `sign(x)*ceil(abs(x)*10^n)/10^n`, `trunc(x,n)` |
| `ABS` | 숫자→숫자 | 전파 | - | 같음 | `abs(x)` |
| `MIN MAX`(2개 이상), `SUM`(1개 이상) | 숫자…→숫자 | **전파 확정**(`03b` 6-1) | - | 엑셀은 빈 칸을 건너뜀 | `least`/`greatest`/`a+b+…` (PG 기본은 NULL 건너뜀이라 전파 감싸기 필요) |
| `LEFT RIGHT(글자,n)` | 글자,숫자→글자 | 전파 | n<0 또는 n>10000 (E2) | 같음(n 소수 버림) | `left(s, trunc(n)::int)` |
| `LEN`, `TRIM` | 글자→숫자 / 글자 | 전파 | - | TRIM은 안쪽 연속 공백도 하나로(엑셀과 같게). LEN은 코드포인트 수(NFC 전제) | `char_length`, `btrim(regexp_replace(s,' +',' ','g'))` |
| `YEAR MONTH` | 날짜→숫자 | 전파 | - | 같음 | `extract(…)` |
| `DATE(연,월,일)` | 숫자 3개→날짜 | 전파 | 결과 연 1~9999 밖, 일이 ±100000 밖 (E3) | 월·일 넘침은 엑셀처럼 이월(2월 30일→3월 2일), 소수 버림 | `make_date(y',m',1) + (d-1)`, y'·m'는 `floor`·`mod()` 함수로 계산 |
| `SUMTAG("태그")` | 글자 상수→숫자 | `SUM`과 같음 | - | 엑셀에 없음. 같은 달 안 `SUMIF` 대응: 같은 태그의 숫자 열 전부 합산, 새 열 자동 포함 | 컴파일 때 태그 열 목록(열 번호 순)으로 펼쳐 `SUM` 규칙 |
- 오류 코드 E1 0으로 나눔, E2 글자 길이 인수 범위, E3 날짜 범위 **[제안]**(05 오류 코드 후보와 별개로 셀 단위 코드). 열 태그는 숫자 열에만, 열마다 하나, 길이 50자 이내·`"`·제어문자 금지 **[제안]**(`SUMTAG("태그")` 재파싱이 깨지지 않게). 태그 이름은 컴파일 때 열 목록으로 풀려 SQL에 글자로 나가지 않는다. 합계 열이 자기 태그를 합산하면 순환이라 거부(§7). 선택 목록(`choice`) 열은 수식에서 글자로 취급 **[제안]**(코드값 비교는 §11).

## 3. 의미 규칙 (`03b` 5-2 K7)
| 규칙 | 내용 | 수식 도움말 문구 제안 |
| --- | --- | --- |
| 미입력 | 0이 아니라 NULL 유지, 결과도 빈 값(함수별 `null_policy`) | "비어 있는 칸은 0이 아닙니다. 계산에 쓴 칸 중 하나라도 비어 있으면 결과도 빈 값입니다. (엑셀은 빈 칸을 0으로 계산합니다.)" |
| 오류 칸 | 값은 빈 값(NULL) + 오류 코드는 §3-1. 0 나누기·날짜 범위 등은 전부 이 규칙, DB 예외로 뷰 조회가 깨지면 안 됨. 피할 수 없는 대체값은 `IFERROR` | "0으로 나누는 것처럼 계산할 수 없는 칸은 빈 값이 되고 점검 화면에 표시됩니다. 다른 값을 쓰려면 IFERROR를 쓰세요." |
| 글자 비교 | `=`·`<>`만, 양쪽 `lower()`. `lower()`의 DB 로케일 의존은 확인하지 못함 | "글자 비교는 대문자·소문자를 구별하지 않습니다." |
| 형 변환 | 숫자·글자·날짜 사이 자동 변환 없음. 어긋나면 C0 오류(날짜-글자 직접 비교 포함) | 쉬운 말 오류 문구 |
| 정규화 | 글자 상수·입력 값은 NFC로 정규화 **[제안, entry·05·06 영향]**. NFD와 NFC는 DB에서 `=`이 거짓(X-26.4, 확인됨) | - |
| 숫자·시간 | 숫자는 모두 `NUMERIC`, 상수 38자리 이하. FU-1 함수에 현재 날짜가 없어 DB 시간대 영향 없음(`TODAY`는 후속, X-8) | - |
- 상수 오류는 DB에 보내지 않는다: PostgreSQL 16 문서가 "상수 `1/0`은 쓰이지 않는 `CASE` 갈래 안에서도 계획 시간에 실패할 수 있고 `CASE`는 철벽이 아니다"라고 명시(`sources/raw/pg16-func.sgml:18255-18265`, 확인됨). 그래서 `/`는 `NULLIF`로 막고, 상수만으로 이뤄진 부분식의 오류(`1/0`, `LEFT("a",-1)`, `DATE(0,1,1)`)는 C0가 거부한다. 방법 **[제안]**: 인수가 모두 상수인 부분식은 사전의 `error_when` 조건 식만(값 식은 실행하지 않음) §4-1 렌더러의 바인드 상수로 읽기 전용 트랜잭션 `SELECT`에 넣어 평가하고, 참이면 C0 거부한다. 사전에 이미 있는 조건 식을 한 번 더 쓸 뿐 파이썬 평가기를 따로 만들지 않으므로 E-C 이중 구현이 아니다. 상수 `SELECT` 한 번에 여러 조건을 묶어 왕복을 줄인다.
### 3-1. 오류와 미입력을 구별하는 구조 **[E-A 승인, 03b 6-2]** (허용 객체 종류: 표·뷰·인덱스·제약뿐)
| 옵션 | 구조 | 장단점 |
| --- | --- | --- |
| **E-A (제안)** | 보조 뷰 `de_<번호>`: `row_id` + 계산 열마다 `e_<열 번호>`(smallint, NULL=정상, 값=오류 코드). `dv_`에는 오류 흔적이 없고 Superset에 등록하지 않음. 그리드·미리보기·점검 화면(S5)이 두 뷰를 `row_id`로 결합 | 장: Superset 열·새로고침 영향 없음, 같은 변환기. 단: 뷰 수 2배(50개 → 100개, 50개 재생성 0.16초 X-17), 이름 규칙 `de_` 추가(04 부록 A 변경), 읽을 때 식 이중 계산 |
| E-B | `dv_`에 `e_` 열을 함께 둠 | 뷰 1개. 단: Superset 열로 노출되어 작성자에게 보이고 열 새로고침에 얽힘 |
| E-C | 파이썬 평가기로 오류 판정 | 이중 구현이라 §6 원칙 위반, 비추천 |
- `RowViewPort`(04 부록 A) 구현: formula가 `dv_`와 `de_`를 `row_id`로 결합해 계산 열 값과 오류 코드를 돌려준다. 그리드(05 C1)·점검(D7·D8)이 이 포트를 쓴다. 대안(판정 SELECT)에서도 포트의 모양은 같다.

## 4. 리터럴과 글자 상수 (`03b` 5-2 Z6 (가))
SQLAlchemy 내장 `CreateView`가 `literal_binds`로 상수를 SQL 텍스트로 렌더한다(설치본 소스 `sql/ddl.py`, X-26, 확인됨). 공식 문서는 이 방식을 "debugging purposes only", "not to be passed to a live production database", "only with local, trusted input"으로 한정한다(`facts-db` Q6, 확인됨). 파라미터 없는 쿼리는 pg8000이 simple query로 보내 **여러 문장이 실행될 수 있다**(X-26, 확인됨). 방어는 우리 규칙과 시험에 달려 있다.
### 4-1. 타입 있는 리터럴 렌더러 (접점 한 곳, 나중에 (나)안으로 옮길 때 이 한 곳만 교체)
| 값 | 뷰와 미리보기가 같은 형태로 렌더 | 거부·제한 |
| --- | --- | --- |
| 숫자 | 유한 `Decimal` → `CAST(… AS NUMERIC)`. 정수도 `Decimal`로 전달(`10**30`의 BIGINT 범위 오류 제거) | `NaN`·`Infinity`(따옴표 없이 렌더되어 열 이름으로 해석됨, X-26.1), 38자리 초과 |
| 글자 | `CAST('…' AS TEXT)` | §4-2 |
| 참거짓 / 날짜 | `CAST(true AS BOOLEAN)` / `CAST('YYYY-MM-DD' AS DATE)`(날짜 상수는 후속 단위, FU-1은 `DATE()` 결과만) | 날짜-글자 직접 비교 금지(C0) |
| 빈 값(사전 내부) | `CAST(NULL AS <형>)` | 형 없는 NULL 금지(바인드 `42P18`, X-26.3) |
| 사전 내부 상수(10, 1 등) | 전부 이 렌더러 경유 | 사전 코드의 `literal()`·`bindparam` 직접 호출을 코드 검사로 0건 확인 |
| 연산자 | `%` 연산자는 문법·사전에 없음(pg8000 컴파일러가 `%%`를 내 뷰 생성이 오류, X-26.3). 필요하면 `mod()` 함수 | - |
### 4-2. 글자 상수 규칙
- 거부: NUL, 서로게이트, 역슬래시, 제어문자(Cc: 개행·탭 포함). 서식 문자(Cf)·줄 구분(Zl·Zp)도 거부 **[제안]**(눈에 안 보이는 문자는 X-26.4의 규칙 R2~R5가 거르지 않음). 길이 200자 **[제안]**(X-26.4 사례), 수식 전체 2,000자 **[제안]**. NFC 정규화 뒤 검사. 팀 열 값(팀 코드)도 같은 렌더러를 쓴다(코드 문자 규칙은 06).
### 4-3. 완화책 3가지와 실행 계정 (`03b` 5-2 Z6, 모두 효과 확인됨 X-26.2)
| 완화책 | 위치 | 비고 |
| --- | --- | --- |
| ① 세션 `standard_conforming_strings` 고정: `connect_args={"startup_params": {"standard_conforming_strings": "on"}}` | core `db.py` 엔진 생성 + 시작 자가 점검에 `show` 확인 추가 **[제안]**(04 §2-1 반영) | 방언은 엔진 첫 연결 때 한 번만 판정해, 서버 설정이 나중에 바뀌면 역슬래시 입력으로 주입 성립(X-26.2 시나리오 A) |
| ② 역슬래시·제어문자·NUL 거부 | 렌더러 입력 검사(C0도 같은 함수) | 1차 방어, 정확성보다 이중 방어·감사 목적 |
| ③ 생성 후 읽기 확인, 불일치 시 롤백 | `ddl` 뷰 생성 함수(formula가 확인 질의 목록 전달) | 같은 트랜잭션에서 글자 상수만 담은 확인 `SELECT`를 같은 렌더러로 실행해 입력과 같은지, 뷰를 `LIMIT 0`으로 읽어 열 이름·개수가 기대와 같은지 비교. **사후 롤백**이며 뷰 식 안 상수 위치의 직접 비교는 아님: 충분성은 구현 첫 시험에서 확인(확인하지 못함) |
- 런타임 DDL은 반드시 `bi_app`으로 실행해 피해를 `bi_data`로 한정한다. 단 `bi_app`은 정적 표 DML이 있어 주입이 성립하면 정적 표 행 변경·삭제는 가능하다(X-15, 확인됨). 방어선은 위 3중 + 회귀 시험이다. `text()`·`exec_driver_sql` 0건은 AST 검사로 시험한다(X-26.5 방식).
### 4-4. FU-1 회귀 시험 (고정)
- 주입 10종(X-26.2의 P1~P10, 파이썬 이스케이프 표기):
  `"x'); DROP TABLE public.t; --"`, `"x'; CREATE TABLE bi_data.evil(a int); --"`, `"x' AS c; DELETE FROM public.t; --"`, `"x\\'; DELETE FROM public.t; --"`, `"\\'; CREATE TABLE bi_data.evil(a int); --"`,
  `"x\\''; CREATE TABLE bi_data.evil(a int); --"`, `"$$; DELETE FROM public.t; --"`, `"x' || (SELECT string_agg(v, ',') FROM public.t) || '"`, `"x' UNION SELECT 'leak' --"`, `"x\\\\'; CREATE TABLE bi_data.evil(a int); --"`. 역슬래시 사례: 위 4개와 `a\b`, `a\'b`(정상 입력으로서의 왕복).
- 층별로 모두 시험: L0 전체 구성(②가 역슬래시 포함 입력을 거부) / L1 ②를 끄고 ①만 / L2 ①을 끄고 서버 설정을 `off`로 바꾼 시나리오 A에서 ③만 / L3 렌더러 단독(`on`·`off` 두 설정). 판정: 효과 0건(추가 문장이 실행됐더라도 롤백되어 `bi_data.evil` 없음, `public.t` 행 수 불변, 뷰의 글자 값이 입력과 같거나 롤백 후 변경 전 상태). L2의 ③은 사후 롤백이라 "문장 미실행"이 아니라 "효과 없음"을 판정한다. 정상 구성 10종×2설정은 추가 문장 0건·왕복 일치였다(X-26.2, 확인됨).

## 5. 미리보기 (C1-a, `03b` 2-3 W7)
| 항목 | 내용 |
| --- | --- |
| 계산 | 뷰와 같은 변환기로 `ds_<번호>` 전체를 계산해 기준 날짜(없으면 `row_id`) 최근 순 **20행** 표시 **[제안, 03b 2-5 B5]**. 오류 칸·빈 값 수는 전체 행 대상 집계 1회(같은 트랜잭션) |
| 응답 내용 | 행별 {`row_id`, 기간, 값, 오류 코드}, 전체 오류·빈 값 개수, C0 메시지. DB 예외는 사용자에게 `FORMULA_RUNTIME_ERROR`("수식을 계산할 수 없습니다")로만 정규화하고 내부 로그에 남김 **[제안]** |
| 격리 | `bi_app` + 읽기 전용 트랜잭션 + 트랜잭션별 `statement_timeout` 5초(`set_config`, `03b` 4-5) **[제안 값]**. X-2: 쓰기·`CREATE`·`nextval` 차단은 확인됨이나 사용자 SQL 방어선이 아닌 **이중 장치**(첫 쿼리 전 해제 가능). 실제 방어는 SQL을 사용자가 쓰지 않고 변환기가 만들며 값이 바인드라는 구조 |
| 성능 | 일 단위 3.6만 행 약 0.2초, 월 단위 1ms 안팎(X-9, 모의 데이터·메모리·동시 접속 미측정) |
| 시점 | 입력 후 약 1초 뒤 자동 + 버튼 **[03b 2-5 B6]**. 연결 풀은 5개(`max_overflow` 0, `backend/app/db.py`)라 사용자당 동시 1건만으로는 고갈을 막지 못하므로 **전역 동시 상한 2건**(미리보기·오류 칸 조회 등 무거운 읽기 공통, 일반 요청용 연결 3개 확보)을 둔다 **[제안]**. 초과는 `PREVIEW_BUSY` |
| 한계 | 미리보기 성공이 저장 성공을 보장하지 않음(동시 정의 변경 → 정의 버전 확인). pg8000 경유 읽기 전용 지정(`postgresql_readonly` 실행 옵션 또는 `set_config`)은 확인하지 못함(X-2는 psql 기준), 첫 시험 대상. 대안(비채택 **[제안]**): 미리보기도 리터럴 렌더로 실행하면 불일치가 구조적으로 사라지나 미리보기에도 주입 표면이 생긴다 |

## 6. 미리보기와 뷰 결과 일치 (합격 기준 "불일치 0건", `03b` 5-2)
같은 표현식 객체에서 미리보기는 바인드, 뷰는 리터럴 렌더로 나가므로 차이는 상수 렌더와 상수의 DB 형 추론에서만 생긴다. 평범한 `literal()`은 346건 중 98건이 달랐고 `CAST` 후에도 22건이 남았다(X-26.3, 확인됨). 원인과 설계:
| 남은 22건의 원인 (X-26.3) | 건수 | 설계 |
| --- | --- | --- |
| 바인드만 오류: `10**30`이 BIGINT 범위 초과 | 11 | 모든 숫자 상수 `Decimal` → `CAST NUMERIC`(§4-1) |
| 바인드만 오류: 날짜와 글자 직접 비교 | 3 | C0가 거부(§3 형 변환 규칙) |
| 뷰만 오류: `%` 연산자 | 5 | 문법·사전에 `%` 없음(`mod()`는 FU-1 함수 세트에 없고 후속) |
| 양쪽 오류: `10**30 % 7`, `0/0`, `None + 1` | 3 | 결과는 같지만 메시지 차이를 막으려 모두 "수식 오류"로 정규화: `%`는 문법 밖, `0/0`은 상수 오류라 C0 거부(열 값 0은 오류 칸), `None`은 상수로 존재하지 않음(빈 값은 열 값). 변환 뒤에도 DB 예외가 나오면 시험 실패 |
- **차분(differential) 시험 매트릭스** = 합격 기준(원 346건은 전수가 아니었으므로 확대, 사전 항목이 늘면 자동 확대):
| 축 | 내용 |
| --- | --- |
| 함수 × 인수 구성 | 사전 전체(연산자 포함) × 타입이 유효한 조합. 2인수까지 전수, 3개 이상은 쌍별 **[제안]** |
| 값 변형 | 숫자 {0, 1, -1, 0.1, 0.5, 1.5, 2.5, -2.5, 1E-7, 10**30, 38자리}, 글자 {빈 문자열, 한글, `O'Brien`, 대소문자 혼합, 앞뒤·안쪽 연속 공백, NFC/NFD 쌍, 200자}, 참거짓, 날짜 {윤일, 월말, 0001-01-01, 9999-12-31}, 빈 값 |
| 출처 | 수식 상수 / 원본 열 값 / 계산 열 참조(펼침) |
| 비교 항목 | 값 문자 표기, `pg_typeof`, 오류 코드, DB 예외 여부 — 미리보기 결과 vs 뷰 읽기 결과 |
| 합격 | 불일치 0건, DB 예외 0건, C0 거부 기대 사례는 양쪽 모두 거부 |
- 의미 정확성은 차분이 못 잡으므로 별도 항목: NFC/NFD 정규화(§3), 문서화한 엑셀 차이 규칙(실제 Excel과의 대조는 하지 않음: 클라우드에 Excel 없음, 확인하지 못함), `ROUND` 경계값과 `lower()` 로케일.

- 파서 규칙: ① 행 구분 `\r\n`·`\n`·단독 `\r`(따옴표 밖), 끝 구분자 하나 무시, 빈 중간 행 보존. ② `"`로 시작하면 따옴표 셀: `""`→`"`, 닫는 `"` 뒤가 탭·줄바꿈·입력 끝일 때만 닫힘, 안의 탭·줄바꿈은 내용, 안의 `\r\n`은 `\n`. ③ 따옴표 셀을 읽다 닫힘 조건이 안 맞으면 셀 시작으로 되돌려 따옴표 없는 셀로 다시 읽음(1회). ④ 되돌림 없이 끝까지 안 닫히면 **붙여넣기 거부**.
- ⑤ 공백 안 자름, NUL 거부, 행마다 셀 수가 달라도 허용. ⑥ 문자열 배열만 반환하고 숫자·날짜 해석은 열 타입 쪽에서 하며 모호하면 오류 표시. ⑦ 5,000행과 요청 상한(05 C4: A안 1MiB 이하 승인), 서버가 다시 검증.

## 10. 승인 상태 (`03b` 6-2·6-3)
- 새 런타임 의존성: `lark`(MIT는 브리프 4.5 기재, 패키지 버전·라이선스 확인 후 FU-1d 착수 때 요청). `graphlib`은 표준 라이브러리라 의존성이 아님(문서 미대조).
- 새 환경변수: 없음(타임아웃·길이·재시도·`lock_timeout` 값은 코드 상수 **[제안]**, 변수로 빼려면 승인 필요). 기준선과 다른 설정: `startup_params`는 03b 5-2 Z6로 이미 결정됨. 시작 자가 점검 항목 추가와 `de_<번호>` 이름 규칙은 승인됨(통합 AP-14).
- 승인된 **[제안]**(`03b` 6-2; `MIN`·`MAX`·`SUM`·`SUMTAG` 빈 칸 전파는 6-1 직접 결정): 오류 판정 구조 E-A, 함수 이름 `SUMTAG`와 `[열 이름]` 문법·열 이름 금지 문자, 글자 상수 제한(200자·서식 문자 거부·NFC 정규화), `ROUND*` 자릿수 상수 제한, 글자 `&`의 숫자 자동 변환 불가·글자 대소 비교 제외, 상수 부분식 검사 방식, 미리보기 전역 동시 상한.

## 11. 후속 기능 단위에서 결정
- 이전 행 참조·누적합·증감과 뷰 층 나누기(윈도 함수), 순환 간선 종류. 일부 칸이 비는 것이 정상인 항목이 생기면 "건너뛰는 합계" 함수를 함수 사전에 추가(`03b` 6-1).
- 같은 데이터셋 집계와 Superset 차트로 대체 가능한 집계의 제외 목록. 기준값 표와 기준값 호출(숫자·글자 형식 검사), 공통 요약.
- 함수 확장(엑셀 실제 함수 목록을 받은 뒤): `TODAY`·`EDATE`·`EOMONTH`·`DAY`·`IFS`·`ISBLANK`·`AVERAGE`·`MOD`·`VALUE`·`MID`·`CONCAT`·`SUBSTITUTE`·조건 집계 등. 날짜 산술, 글자 대소 비교, 글자 상수의 줄바꿈 표현.
- 소급 변경·마감(K5), 변경 기록(`audit_log`)에 수식 이전 값 기록, 보관 행·보관 열이 뷰와 수식에 미치는 영향.
- 선택 목록 코드값 비교와 참조 열 검증, 정규식 검증, 글자 상수의 (나)안(별도 표) 이전(`03b` 4-3 Z6). 엑셀 가져오기 규격(강화 사전 검사, 적재 시간 측정), 실제 Excel 클립보드 검증.
