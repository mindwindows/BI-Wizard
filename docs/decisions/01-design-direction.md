# 01. 디자인 방향

- Gate: ① RESEARCH & DECIDE
- 승인일: 2026-10-11 (사용자 승인)
- 해결하는 미결정: 브리프 5절 5번(디자인 방향)
- 근거 조사: 디자인 3안(A 워크북형, B 콘솔형, C 3분할 작업공간) 비교와 reviewer 교차검증을 거쳤다. 조사 초안은 `_workspace/gate1/design-options.md`(Git 제외)에 있고, 이 문서에는 승인된 결정과 그 근거만 옮겼다.

## 결정

1. **방향 C(3분할 작업공간)를 기본으로 한다.** 중앙에 AG Grid(Community), 열 또는 셀을 선택하면 오른쪽 **Inspector** 패널이 그 열의 속성(열 기본, 검증, 권한, 수식)으로 바뀐다. 정의와 입력이 한 화면에서 이어진다.
2. **데이터셋 목록, 권한 관리, 가져오기 앞 두 단계는 방향 B(콘솔형) 화면을 쓴다.**
   - 포털 셸: 상단 글로벌 Navigation, 데이터셋 목록 페이지(이름, 소유자, 원본 파일, 생성일 등 등록 테이블 메타데이터).
   - 권한 관리: 역할 × 데이터셋 격자, 변경 후 저장 시 변경 요약 확인.
   - 가져오기: 전체 화면 단계형 마법사 중 앞 두 단계(업로드, 시트·범위 선택). 이후 단계(헤더, 열 타입 제안, 확인)는 C의 미리보기 그리드 + Inspector를 재사용하는 방향이다(아래 "열린 사항" 참고).
   - 데이터셋을 열면 C의 3분할 작업공간으로 들어간다.
3. **기준 해상도는 1920×1080이다.**
   - Inspector 패널은 **접기와 폭 조절이 가능**해야 한다.
   - 더 작은 화면에서도 그리드를 쓸 수 있어야 한다. 입력 전용 사용자는 Inspector를 접은 상태를 기본값으로 쓸 수 있게 한다.

## 근거

- 가장 어려운 사용 장면은 비개발자가 열 정의와 수식을 만들면서 결과가 맞는지 바로 확인하는 일이다. C는 그리드와 수식 편집 영역을 동시에 열어 둘 수 있고, 오류·자동완성을 위한 공간이 있다(브리프 4.5절의 "열 이름 자동 완성, SQL 용어가 아닌 오류 표시").
- AG Grid Community에는 사이드바, 툴 패널, 컬럼 메뉴, 우클릭 메뉴가 없다(Enterprise). Inspector는 그리드 밖 React 컴포넌트이므로 이 제약이 UI 결함으로 드러나지 않는다.
- 가져오기 확인 단계, 데이터셋 정의, 수식 편집에 같은 Inspector 컴포넌트를 쓸 수 있어 MODULARIZE에서 재사용이 쉽다.
- 관리 화면(목록, 권한)은 C만으로는 부족하므로 B의 화면을 차용한다. B는 되돌릴 수 없는 작업 전 미리보기(가져오기, 타입 변경 확인, 권한 변경 확인)를 넣기 쉽다.

## 가져올 요소와 피할 요소

**C에서 가져온다**
- 오른쪽 Inspector 구조(섹션: 열 기본, 검증, 권한, 수식), "원본 열 / 수식 열" 구분, 편집 가능·읽기 전용 표시, 헤더의 수식 열 아이콘.
- 수식 에디터: 열 이름 칩, 목록 필터링과 삽입, 선택 요소 설명 영역, 오류·영향 패널(이 열을 참조하는 열, 순환 참조 경고).
- 단, 라이브 미리보기와 자동완성(예시 값 포함)은 저장 전 수식 평가 경로가 필요하다(브리프 5절 6번, Gate ③ 결정). 확정된 기능으로 보지 않는다.

**B에서 가져온다**
- 글로벌 Navigation, 데이터셋 목록(메타데이터 열), 역할 × 데이터셋 권한 격자와 저장 전 변경 요약 확인창.
- 가져오기 단계명과 단계별 미리보기, "새 테이블 / 추가 / 교체" 선택.

**피한다**
- AG Grid Community에 없는 기능에 의존하는 설계: 다중 셀 범위 선택, 우클릭 컨텍스트 메뉴, 행 그룹, 값 체크박스 목록 필터(Set Filter), 헤더 컬럼 메뉴, 표 행 펼침 상세(마스터/디테일), 클립보드 기본 기능. 붙여넣기는 브라우저 paste 이벤트로 직접 구현한다(브리프 4.4절). `ag-grid-enterprise`는 쓰지 않는다.
- 수식 오류를 "Unknown error"나 "syntax error" 같은 일반 문구로만 보여 주는 구조. 어디서 쓰이는지 볼 수 없는 열 참조 구조.
- "오류가 있어도 저장 가능" 방식. 뷰 반영은 오류가 없을 때만 한다.
- Lists의 한계: Excel을 표 서식으로 만들어야 하고, 기존 목록에 못 넣고, 병합 셀·빈 행에서 감지 실패를 사용자에게 넘기는 구조.

## 열린 사항 (이 결정으로 정해지지 않은 것)

- **수식 미리보기·자동완성 경로:** 브리프 5절 6번. Gate ③에서 결정한다.
- **Explore(Superset 차트 작성 화면) 제공 방식:** 브리프 5절 7번. Embedded SDK로 가능한 범위를 공식 문서로 확인한 뒤 Gate ③에서 결정한다.
- **가져오기 형태(모달 / 전체 화면):** 이번 조사에서 근거를 확인하지 못해 정하지 않았다. 앞 두 단계는 B의 전체 화면 단계형을 쓰기로 했고, 이후 단계의 상세 구성은 Gate ③ MODULARIZE에서 모듈 경계와 함께 정한다.
- **조합에서 선택하지 않은 요소:** 방향 A의 툴바·행 높이 전환 등 A 고유 요소와 "공통 요소"(행 높이 전환, 대시보드 탭 내 Superset iframe 옵션 동기화)는 이번 승인 대상이 아니다. 필요하면 Gate ③ 이후 별도로 제안한다.
- **조사의 한계:** 벤더 사이트(Microsoft, Airtable, Notion, Baserow, AG Grid, Superset 등)는 이 환경에서 열리지 않아 화면 서술의 상당 부분이 검색 요약 기준이다. 스크린샷을 볼 수 없어 색, 서체, 간격 같은 시각 언어는 확인하지 못했다. Notion 수식 편집기의 인라인 오류 표시는 미확정이다. 시각 언어는 이후 단계에서 별도로 정한다.
- 개발량·정보 밀도 비교는 조사자의 추정이며 실측이나 견적이 아니다.
- AG Grid Community 포함 여부가 자료마다 다른 항목(Undo/Redo, 행 고정)은 프로토타입에서 확인한다.
